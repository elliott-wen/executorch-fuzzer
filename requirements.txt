# mobile fuzzer — Python dependencies
#
# Target: Python 3.12 (the gold env at /data/jwen929/pytorch/venv is 3.12.13).
# Install into a CPU-only venv (see README / setup notes):
#
#     python3.12 -m venv .venv
#     .venv/bin/python -m pip install -U pip
#     .venv/bin/python -m pip install -r requirements.txt
#
# IMPORTANT — CUDA is intentionally NOT used here.
#   * The fuzzer is CPU-only by design (CUDA_VISIBLE_DEVICES="" everywhere; portable
#     CPU kernels are the faithful mobile stand-in — see docs/overview.md).
#   * The CUDA environment on this host is unreliable for our purposes: the system
#     python3.9 ships torch 2.8.0+cu128 (a CUDA build), nvcc/CUDA toolkit is absent,
#     and the GPUs are shared/contended. We therefore pin the +cpu torch build pulled
#     from the PyTorch CPU index below. Do NOT install a +cuXXX torch here.
#
# The +cpu wheels (torch, torchao, executorch) live on the PyTorch CPU indexes, not PyPI.
# executorch is now the 1.5.1 STABLE release (was the 1.4.0.dev20260625 nightly). Stable
# wheels are not garbage-collected, so this pin does not rot. NOTE the consequence: the
# pytorch_ref/executorch source tree is still 1.4.0a0, so any runner BUILT FROM SOURCE
# (ethos-u FVP, vulkan, vgf, cadence, nxp) now skews against the .pte this wheel serializes
# and must be rebuilt from a 1.5.1 checkout before it can be trusted.
--extra-index-url https://download.pytorch.org/whl/cpu

# --- Core: graph lowering + runtime -----------------------------------------
# executorch pulls torchao, coremltools, numpy, sympy, flatbuffers, etc. torch is pinned
# explicitly to lock the CPU build. executorch declares no torch requirement of its own, so
# this pin is the ONLY thing choosing the ATen version the whole pipeline is generated
# against — keep the two bumped together.
executorch==1.5.1+cpu
torch==2.14.0+cpu

# --- Constraint solver (graph generation) -----------------------------------
z3-solver==4.16.0.0

# --- Transport (broker / feed / client) -------------------------------------
# NOTE: not present in the gold venv (the networking side was never run from it),
# but net/{broker,feed,client,protocol}.py import `zmq`. Required to run the fleet.
pyzmq==27.1.0

# --- Qualcomm (QNN) backend -------------------------------------------------
# executorch.backends.qualcomm.__init__ hard-requires cpuinfo; without it the import
# raises and the backend silently drops out of available_backends() ("env not sourced
# / SDK missing?"). Needed for the qualcomm/QNN pregen corpus.
py-cpuinfo==9.0.0
